# Argo 메신저 모바일

iPhone과 Android에서 데스크톱과 같은 계정·조직·채널을 사용한다. 휴대폰은 Supabase에 직접 연결하며, 사용자의 PC 주소나 SSH/Tailscale 설정을 요구하지 않는다. 에이전트 실행은 등록된 상주 서버가 담당하므로 그 서버의 연결 상태는 별도로 유지되어야 한다.

## 구현 범위

- 기존 채널 대화, 멘션, 결재, 설정 화면을 모바일 네이티브 셸에서 공유한다.
- 로그인은 시스템 브라우저와 PKCE를 사용한다. 앱 재시작 후 복귀, 취소, 중복 콜백, 만료를 처리한다.
- 세로·가로 화면, 화면 안전 영역, 키보드에 맞춰 대화와 입력창을 배치한다. 모바일 Enter는 줄바꿈이며 전송 버튼으로 보낸다.
- 앱 복귀·재연결 시 메시지를 다시 조회한다. 일시적인 인증 갱신 오류로 대화와 작성 내용을 지우지 않는다.
- 컴퓨터의 헤르메스·오픈클로 설치와 데스크톱 업데이터는 모바일에서 실행하지 않는다.

## 검수와 배포 구분

현재 작업은 모바일 검수 버전이다. 앱이 닫혀 있을 때의 원격 푸시 알림은 구현하지 않았으며 설정 화면에도 이 상태를 표시한다. APNs/FCM 등록·서버 발송·알림 선택 시 대화 열기는 정식 모바일 배포 전 별도 구현·검수 대상이다.

Android debug APK는 테스트 설치용이다. iOS simulator 앱은 실제 iPhone에 설치할 수 없다. 실제 iPhone 설치·TestFlight·양쪽 스토어 배포에는 Argo에 사용할 개발자 계정, 해당 앱의 서명·프로비저닝과 배포 설정이 필요하다. 다른 제품의 인증서를 자동 재사용하지 않는다.

지원 기준은 iOS 16.4 이상, Android 7 이상과 최신 Android System WebView다. 이 기준은 설치·번들의 최소 요건이며 모든 해당 OS 버전을 실측했다는 뜻이 아니다.

## 개발 및 확인

- [네이티브 빌드](docs/mobile-build.md)
- [모바일 인증 계약](MOBILE-AUTH.md)
- `npm test` — 인증·복귀 시나리오 회귀 검사
- 실제 검수 증거는 저장소의 `artifacts/mobile-native/`, `artifacts/mobile-ui/`, `artifacts/mobile-auth/`에 별도 보관한다. 자격증명·빌드 산출물을 소스 커밋에 포함하지 않는다.

검수용 비밀번호 로그인은 `VITE_DEV_LOGIN=1`인 격리 빌드에서만 쓴다. 사용자에게 전달할 클라우드 빌드에서는 반드시 제거한다. 빌드 성공, 시뮬레이터 테스트, 실제 휴대폰·공급자 로그인, 스토어 배포를 서로 구분해서 보고한다.
