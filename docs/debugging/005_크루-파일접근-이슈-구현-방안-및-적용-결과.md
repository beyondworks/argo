## 권고 2: `read_file` 출력에 바이트 크기 필드 추가

### 배경

`read_file` 도구의 반환 형식에 바이트 크기가 없어서, LLM이 크기를 자체 추정했습니다. 이로 인해 SHA-256은 일치하지만 크기는 불일치하는 모순이 발생했습니다.

### 변경 내용

[`src/openai-compat-tools.mjs`](file:///home/bhlee/services/argo_agent/argo/src/openai-compat-tools.mjs#L211)

```diff
-const output = `${abs}\nsha256:${sha256}\n${selected}\n\n[lines ${offset}-${end} of ${lines.length}]`;
+const output = `${abs}\nsha256:${sha256}\nsize:${body.length}\n${selected}\n\n[lines ${offset}-${end} of ${lines.length}]`;
```

### 동작 방식

변경 전 `read_file` 출력:
```
/home/.../vault/files/msa4ac58wkp-상품-선정-방법론.md
sha256:9df103a6f1ff29450fc3fa99647308800c88ef8aee6cdc87052106c5b726e4dd
1: # YouTube·블로그·SNS 기반 쿠팡 소싱 상품 선정 방법론
2: ...

[lines 1-190 of 190]
```

변경 후 `read_file` 출력:
```
/home/.../vault/files/msa4ac58wkp-상품-선정-방법론.md
sha256:9df103a6f1ff29450fc3fa99647308800c88ef8aee6cdc87052106c5b726e4dd
size:13154
1: # YouTube·블로그·SNS 기반 쿠팡 소싱 상품 선정 방법론
2: ...

[lines 1-190 of 190]
```

LLM은 이제 `size:` 행에서 정확한 바이트 크기를 읽을 수 있으므로, 자체 추정에 의한 크기 불일치 문제가 해소됩니다.

### 검증

```
✅ node --check src/openai-compat-tools.mjs — 통과
```

## 권고 4: 도구 호출 상세 로깅 강화

### 배경

현재 `events.jsonl`에는 도구 호출 횟수만 기록되고, 개별 도구 호출의 성공/실패와 출력 스니펫은 기록되지 않습니다. 이로 인해 LLM 환각(도구를 호출하지 않고 텍스트로 서술)과 실제 도구 실패를 구분할 수 없었습니다.

### 변경 내용

#### 파일 1: [`src/runners/deepseek-local.mjs`](file:///home/bhlee/services/argo_agent/argo/src/runners/deepseek-local.mjs)

**시그니처에 `onToolResult` 콜백 추가** (L117):

```diff
   onToolCall = async () => {},
+  onToolResult = async () => {},
   validateFinal = null,
```

**도구 실행 후 콜백 호출** (L208):

```diff
   const record = { id, name, args, output: String(output ?? '').slice(0, 120_000) };
   calls.push(record);
+  await onToolResult({ name, args, id, round, output: record.output,
+    ok: !record.output.startsWith('도구 호출 오류(') });
   messages.push({ role: 'tool', tool_call_id: id, name, content: record.output });
```

#### 파일 2: [`src/chat.mjs`](file:///home/bhlee/services/argo_agent/argo/src/chat.mjs)

**핸들러 등록** (L1167-1170):

```javascript
onToolResult: async ({ name, id, output, ok }) => {
  const snippet = String(output ?? '').slice(0, 200).replace(/\s+/g, ' ');
  step(ok ? 'tool_ok' : 'tool_err', `${name}(${id}): ${snippet}`);
},
```

### 동작 방식

```mermaid
sequenceDiagram
    participant LLM as Qwen 3.6 27B
    participant Loop as Tool Loop
    participant Gate as Permission Gate
    participant FS as File System
    participant Log as events.jsonl

    LLM->>Loop: tool_call: read_file({path: "vault/..."})
    Note over Loop,Log: onToolCall → step('reading', 'vault/...')
    Loop->>Gate: 경로 검증
    Gate->>FS: fs.readFile()
    FS-->>Gate: 파일 내용
    Gate-->>Loop: 성공 (abs + sha256 + 내용)
    Note over Loop,Log: onToolResult → step('tool_ok', 'read_file(id): /path sha256:...')
    Loop-->>LLM: role=tool 결과 반환

    Note over Log: events.jsonl에 steps 배열로 기록<br/>환각 시: onToolCall 없음 → steps에 도구 호출 기록 없음<br/>실패 시: step('tool_err', ...) 기록
```

이제 `events.jsonl`의 `steps` 배열에 다음이 기록됩니다:

| 시나리오 | steps 기록 |
|----------|------------|
| **LLM 환각** (도구 미호출) | `onToolCall`·`onToolResult` 모두 없음 → steps에 도구 관련 기록 없음 |
| **도구 호출 성공** | `{ stage: 'reading', ... }` → `{ stage: 'tool_ok', detail: 'read_file(id): ...' }` |
| **도구 호출 실패** | `{ stage: 'reading', ... }` → `{ stage: 'tool_err', detail: 'read_file(id): 도구 호출 오류...' }` |
