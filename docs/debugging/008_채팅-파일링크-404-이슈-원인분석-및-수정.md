# 채팅 파일 링크 클릭 시 404 (찾을 수 없음) 이슈 근본 원인 해결 보고서

> **수정일**: 2026-08-12 23:15 KST

---

## 1. 추가 원인 분석 (2차 정밀 조사)

1. **프로젝트 접두사(`projects/`) 생략 및 파일명만 제시된 링크 처리 불가**
   - 크루가 마크다운 답변 시 `projects/20260812_크루-파일접근-이슈-개선/001.md` 대신 `20260812_크루-파일접근-이슈-개선/001.md` 또는 `001.md` 처럼 파일명만 남기는 경우가 다수 발생.
   - 기존 백엔드 `readDoc`은 단순 `resolve(p.vault, rel)`만 수행하여 해당 위치에 파일이 없으면 즉시 `ENOENT` 404 `문서를 찾을 수 없습니다` 에러를 반환함.

2. **비-md 산출물 서빙 경로 미보정 (`app/api/companies/[ws]/files/route.js`)**
   - 비-md 파일(PDF, PNG, PPTX, HTML 등) 링크 시 `projects/` 접두가 생략되어 요청되면 `files/route.js`에서 `files/`, `projects/`, `_imported/` 접두검사에 걸려 `잘못된 경로` 400 에러가 반환됨.

---

## 2. 해결 내용

### 1) 스마트 `readDoc` 탐색 알고리즘 도입 (`src/hub.mjs`)
`readDoc` 함수에 5단계 자동 탐색/보정 알고리즘을 도입하여 어떠한 경로 표현이라도 정답 파일을 찾아내도록 구현:
1. **1단계 (경로 정제)**: 절대 경로(`/home/.../vault/`), `vault/`, `./` 접두사 제거
2. **2단계 (직접 매칭)**: `rawFile` & `.md` 시도
3. **3단계 (접두사 보정)**: `projects/${rel}`, `notes/${rel}` 자동 시도
4. **4단계 (재귀 파일명 탐색)**: `vault` 하위 디렉토리를 재귀 탐색하여 `targetBase` 파일명과 일치하는 실재 파일을 발견 시 읽기 시도
5. **5단계 (일지 보관함)**: `journal/.archive/` 탐색

### 2) `files` API 경로 자동 보정 (`app/api/companies/[ws]/files/route.js`)
- `projects/` 접두사가 누락되어 들어오는 요청에 대해 vault 실제 파일 존재 여부를 체크하여 자동 보정.
