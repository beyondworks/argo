# 001_DeepSeek_러너_에러_분석

## 1. 개요
사용자가 로컬 DeepSeek 서버(`100.103.65.62:8080`)를 연동하기 위해 "이 컴퓨터 로그인 사용"을 클릭했으나 활성화되지 않는 문제와, 대화 시 "지정 러너 Claude Code가 이 기기에 연결돼 있지 않아 Codex로 대체 실행됐습니다"라는 에러 다이얼로그가 발생하는 문제에 대한 분석 및 조치 내용입니다.

## 2. 현상 및 원인 분석

### 2.1 "이 컴퓨터 로그인 사용" 버튼 비활성화 원인
- **증상:** "회사 설정 -> API 키/러너 설정" 화면에서 DeepSeek Local 러너의 "이 컴퓨터 로그인 사용" 버튼을 눌러도 활성화(흰색 바탕)되지 않음.
- **원인:** 지난 단계에서 `src/runners/catalog.mjs`에 `deepseekLocal` 러너를 등록할 때, `hostUsable: true` 속성을 누락했습니다. 이 속성이 없으면 프론트엔드(`runner-connect.jsx`)에서 해당 옵트인 기능을 사용할 수 없도록 비활성화합니다.

### 2.2 대화 시 발생하는 에러 원인 (Claude Code 미연결 에러)
- **증상:** 모델을 "Gemini 3.1 Pro (High)" 등 다른 러너의 모델로 변경한 후 대화를 시도하면, 뜬금없이 "Claude Code가 연결돼 있지 않아 Codex로 대체 실행"되었다는 오류가 발생함.
- **원인:**
  1. **잘못된 러너 지정:** 사용자가 모델명은 변경했지만, 해당 크루의 러너 설정(`meta.runner`)이 갱신되지 않거나 기본값(`claude`)으로 남아 있었습니다.
  2. **환경 변수 충돌:** 시스템에 설정된 로컬 LLM 환경 변수(`ANTHROPIC_API_KEY=local`, `ANTHROPIC_BASE_URL=http://100.103.65.62:8080`)로 인해, Argo 시스템은 Claude 러너가 "이 컴퓨터에 연결됨(`connected: true`)" 상태라고 잘못 판단했습니다.
  3. **인증 에러 및 자가치유(Fallback):** Argo가 Claude SDK를 통해 지정된 로컬 서버(100.103.65.62:8080/v1/messages)로 요청을 보냈으나, 해당 서버는 Anthropic SDK의 인증 정보에 대해 `Invalid API Key (401)` 오류를 반환했습니다.
  4. Argo의 `chat.mjs` 로직은 401 오류를 감지하면 "해당 러너(Claude)의 인증이 만료되었거나 문제가 있다"고 판단하여 다음 순위인 `codex` 러너로 자가치유를 시도합니다. 이 과정에서 출력된 메시지가 사용자 화면에 에러 다이얼로그로 표시된 것입니다.

## 3. 조치 사항
1. **`deepseekLocal` 속성 수정:** `src/runners/catalog.mjs` 파일에서 `deepseekLocal` 러너 설정에 `hostUsable: true` 속성을 추가했습니다. 이를 통해 사용자가 "이 컴퓨터 로그인 사용" 기능을 통해 로컬 서버와 연동할 수 있게 됩니다.
2. **패치 파일 갱신:** 기존에 생성했던 `apply-local-patch.sh`를 구동하기 위한 패치 파일(`patches/deepseek-and-claude-local.patch`)을 새 변경사항을 포함하여 갱신했습니다.
3. **서버 재시작:** `systemctl restart argo` 커맨드로 서버를 재시작하여 변경된 카탈로그가 즉시 반영되도록 조치했습니다.

## 4. 향후 사용 가이드
- 회사 설정(Settings) > API 키/러너 설정으로 이동하여 **"DeepSeek Local"** 러너에서 **"이 컴퓨터 로그인 사용"**을 클릭하면 연결이 활성화됩니다.
- 개별 크루(Crew)의 대화창 상단 설정에서 러너를 **"DeepSeek Local"**로 명시적으로 선택하고 대화하시기 바랍니다.
