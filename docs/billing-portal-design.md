# 구독 관리 — 서버 창구 설계

> 결제·구독은 사용자가 **의심 없이** 다룰 수 있어야 한다. 결제는 되는데 해지가 안 되는 상태로
> 사용자를 받으면 환불·분쟁으로 돌아온다. 이 문서는 그 표면을 다른 LLM 서비스 수준으로 만드는 설계다.

## 문제 (2026-08-05 실측)

데스크톱 앱은 **사용자 기기에서 Next 서버를 돌린다.** 그래서 서버 비밀을 앱에 실을 수 없다.

- `LEMONSQUEEZY_API_KEY`를 릴리스 빌드에 넣으면 **전 사용자에게 우리 결제 API 키가 배포된다.**
  그 키로 남의 구독을 조회·변경할 수 있다. 넣으면 안 되는 값이다.
- 안 넣으면 `/api/me/billing/portal`이 `결제 연동이 아직 설정되지 않았습니다`로 죽는다
  (`app/api/me/billing/portal/route.js` — `if (!apiKey) return fail(...)`).
- 같은 키에 `/api/me/billing`의 **대사(reconcile)** 도 묶여 있다(`route.js:36-37`) — 키가 없으면
  웹훅 유실 복구가 조용히 꺼진다.

**결론**: 지금 구조로 결제를 열면 사용자는 **결제는 되는데 해지·카드 변경을 못 한다.** 열기 전에 닫아야 한다.

## 원칙 — 여기서 '깔끔함'의 정의

1. **비밀은 서버에만.** 기기에 내려가는 것은 공개값(체크아웃 링크·플랜 표시)뿐이다.
2. **막다른 길 금지.** 모든 실패 화면에 다음 행동이 있다 — 재시도·지원·업그레이드 중 하나.
3. **상태는 한 곳에서 정직하게.** 플랜·다음 결제일·해지 예약일·연체 유예를 같은 카드에서 본다.
   모르는 값은 지어내지 않는다("확인 중"이 정답일 때가 있다).
4. **해지는 언제나 2클릭 안에.** 찾아 헤매게 만들지 않는다. 붙잡는 문구도 넣지 않는다.
5. **데이터 반환은 결제 상태와 무관하게 항상.** 해지·연체·페이월 어느 상태에서도 내보내기가 보인다
   (이미 `CloudExportRow`가 분기 사슬과 직교로 렌더된다 — 그 원칙을 유지한다).
6. **ko/en 동등.** 결제 문구에 한국어 하드코딩을 남기지 않는다.

## 구조 — 웹훅과 같은 인프라를 쓴다

새 서버를 세우지 않는다. 이미 도는 Supabase Edge Function 옆에 하나 더 둔다.

```
[앱(기기)]  --Authorization: Bearer <supabase access_token>-->  [Edge Function ls-portal]
                                                                   | JWT 검증 → user_id
                                                                   | entitlements.ls_subscription_id 조회
                                                                   | LS API로 신선한 포털 URL 발급
                                                                   ↓
                                                              302 → LS 고객 포털
```

- **키**: `LEMONSQUEEZY_API_KEY`를 **Supabase secret으로만** 둔다(`supabase secrets set`).
  앱 번들·릴리스 CI에는 넣지 않는다.
- **인증**: 사용자 JWT로 본인 확인. `ls_subscription_id`를 클라이언트가 넘기지 않는다 —
  넘기게 하면 남의 구독 id로 포털을 여는 길이 생긴다.
- **클릭 시점 발급 유지**: LS 포털 URL은 24시간 만료 프리사인 링크다. 저장·렌더 금지
  (기존 라우트 주석의 근거 그대로 — 웹훅 스냅샷을 박아두면 정상 구독자 대부분이 죽은 링크를 받는다).

## 상태 표시 — 단일 진실은 `entitlements`

- LS를 **직접 호출하는 것은 서버(웹훅·Edge Function)뿐**이다. 앱과 로컬 서버는 `entitlements`만 읽는다.
- 표시 항목: 플랜 배지 · 다음 결제일 · 해지 예약 시 종료일 · 연체 유예 안내 · 체험 D-day.
- `entitlements`에 없는 값은 화면에서 **생략**한다(추정 금지).
- 이 정리로 `/api/me/billing`에서 LS 직접 호출이 사라진다 → 데스크톱에서도 상태가 정상 표시된다.

## 실패 처리 (데드엔드 금지)

| 상황 | 화면 |
|---|---|
| 구독 없음 | "구독이 없습니다" + 업그레이드 버튼 |
| LS·네트워크 오류 | "잠시 후 다시 시도해 주세요" + 재시도 + 지원 메일 |
| 로컬·게스트 세션 | "로그인하면 구독을 관리할 수 있습니다" + 로그인 |
| 함수 미배포(구버전 앱) | 기존 경로로 폴백, 그것도 없으면 LS 로그인 안내 링크 |

## 이관 순서 (한 번에 바꾸지 않는다)

1. `ls-portal` Edge Function 배포 + secret 주입 → **함수만 단독 검증**
2. 앱 링크를 함수 주소로 교체(구버전 폴백 유지)
3. `/api/me/billing`에서 LS 직접 호출 제거 → `entitlements` 기반으로 정리
4. `LEMONSQUEEZY_API_KEY`를 상주 env에서도 제거(더는 필요 없다)

## 검증

- **실물 왕복**: free 계정 → 구독(100% 쿠폰) → 포털 열기 → 해지 예약 → 화면에 종료일 표시 → 재개
- **키 유출 트립와이어**: 릴리스 산출물과 `.github/workflows/release.yml`에 `LEMONSQUEEZY_API_KEY`가
  없음을 테스트로 잠근다. 이 키가 앱으로 나가는 순간이 이 설계가 무너지는 순간이다.
- **데스크톱 실기기**: 상주(:3001)가 아니라 **설치본**에서 구독 관리 링크가 실제로 열리는지.
  상주는 개발 기기 env를 물고 있어 통과해도 증거가 못 된다.

## 미확인

- 상주 env의 `LEMONSQUEEZY_API_KEY`가 Test 값인지 Live 값인지 확인하지 않았다(이름만 확인).
- LS 고객 포털이 제공하는 항목(카드 변경·인보이스·해지·재개)의 정확한 범위는 대시보드에서 미확인.
  포털이 재개를 지원하지 않으면 재개 경로를 앱에서 따로 만들어야 한다.
