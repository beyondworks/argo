# Qwen/OpenAI 호환 도구 러너 및 Claude 로컬 패치 자동화 가이드

## 1. 개요
Argo를 상위 버전으로 업데이트한 뒤에도 **Qwen 3.6 27B 러너**, **OpenAI 호환 도구 호출·실행 루프**, **파일 읽기 SHA-256·전체 범위 증거 게이트**, **Scrapling 웹 도구**, **회사 MCP 브리지**, **Claude Code 로컬 연동**을 다시 적용할 수 있도록 패치와 검증 스크립트를 둡니다.

## 2. 구축된 파일 및 구조

- **패치 파일**: `patches/deepseek-and-claude-local.patch`
  - 앱·서버·테스트의 로컬 기능 변경을 포함합니다.
  - `package.json`과 Tauri 버전 파일은 제외합니다. 향후 업데이트 버전을 0.1.40으로 되돌리지 않기 위해서입니다.
  - 생성 기준 기능 커밋: `bdb1d30`, `6b75cb9`
  - SHA-256: `bad2cf594952f85afe029178c117b6f3207e49d65fad754f3800a74fb6c3922d`
- **원클릭 적용 스크립트**: `apply-local-patch.sh`
  - 미커밋 추적 파일 및 중복 적용 여부 확인
  - `git apply`, 필요하면 3-way 적용
  - Scrapling 설치, Node.js 구문, Qwen 도구 회귀 테스트 확인
  - 프로덕션 빌드
  - `argo.service` 재시작 후 `/api/ping` 확인

## 3. 업데이트 후 사용 방법

먼저 업데이트 결과를 커밋하거나 작업트리를 깨끗하게 만든 뒤 실행합니다.

```bash
./apply-local-patch.sh
```

적용하지 않고 체크섬·중복 여부·적용 가능성만 확인하려면 다음을 사용합니다.

```bash
./apply-local-patch.sh --check-only
```

## 4. 검증 결과

- 패치가 이미 적용된 상태면 중복 적용하지 않습니다.
- 일반 적용이 실패하면 Git 3-way 적용을 시도합니다.
- 충돌 시 자동으로 성공 처리하지 않고 중단합니다.
- 스크립트 실행 권한을 저장소에 포함합니다.

## 5. 업데이트 방식 선택

- 로컬 브랜치를 유지하는 경우: 상위 변경을 받은 뒤 기능·재적용 워크플로 로컬 커밋을 rebase하는 방식을 우선 사용합니다.
- 깨끗한 상위 소스에 기능만 다시 넣는 경우: `apply-local-patch.sh`를 실행합니다.
- 패치 적용 후 변경은 커밋되지 않은 상태로 남습니다. diff를 검토한 뒤 별도 커밋합니다.
